# Harness Engineering Scoring System (HESS)

PR 이벤트를 트리거로 코드 변경의 품질을 자동 평가하는 시스템. GitHub Actions [[github-actions-reusable-workflow|Reusable Workflow]] 패턴을 활용하여, 중앙 레포에 스코어링 로직을 두고 각 레포는 최소한의 설정만 추가한다.

## 아키텍처

```
┌─────────────────────────────────────────────────┐
│  각 레포 (e.g. frontend-29cm-platform)          │
│                                                  │
│  .github/workflows/harness-scoring.yml (Caller) │
│    on: pull_request [opened, sync, edited, closed]│
│    └── uses: musinsa/harness-engineering-       │
│             scoring-system/.../ingress.yml@main │
│        secrets: inherit                          │
│                                                  │
│  .harness/scoring.yml      ← 레포 설정          │
│  .harness/pr-authoring.json ← PR 가이드 힌트    │
└──────────────────────┬──────────────────────────┘
                       │ workflow_call
                       ▼
┌─────────────────────────────────────────────────┐
│  musinsa/harness-engineering-scoring-system      │
│  (중앙 레포 — Called Workflow)                    │
│                                                  │
│  .github/workflows/harness-scoring-ingress.yml  │
│    - PR 데이터 정규화                            │
│    - 스코어링 로직 실행                          │
│    - 결과 제출                                   │
└─────────────────────────────────────────────────┘
```

## 레포별 설정 파일 구조

### `.github/workflows/harness-scoring.yml`

Caller workflow. PR 이벤트 4가지를 감지하여 중앙 ingress 워크플로우를 호출한다.

```yaml
name: Harness Scoring

on:
  pull_request:
    types: [opened, synchronize, edited, closed]

jobs:
  submit-normalized-ingress:
    uses: musinsa/harness-engineering-scoring-system/
          .github/workflows/harness-scoring-ingress.yml@main
    secrets: inherit
```

- **14줄**로 전체 구성 완료
- `secrets: inherit`로 조직 secrets 자동 전달
- 중앙 로직 변경 시 각 레포 수정 불필요

### `.harness/scoring.yml`

레포의 프로필과 팀 매핑을 정의한다.

```yaml
# Generated by scripts/onboard_repo.py
profile: "frontend/monorepo"
team_mapping:
  "**": "29CM-E Commerce Frontend"
```

| 필드 | 설명 |
|------|------|
| `profile` | 레포 기술 프로필. 스코어링 기준에 영향 |
| `team_mapping` | glob 패턴 → 팀 이름 매핑. `**`는 전체 파일 |

- `scripts/onboard_repo.py`로 자동 생성
- 레포 소유자가 관리

### `.harness/pr-authoring.json`

PR 작성 시 LLM/도구가 참조하는 가이드라인. PR 품질 점수에 영향.

```json
{
  "version": 1,
  "system_context": "레포 프로필 기반 컨텍스트",
  "spec_hints": ["비즈니스 규칙 문서 참조 가이드"],
  "guide_hints": ["운영 런북 참조 가이드"],
  "oracle_hints": ["머지 후 성공 시그널 기술"],
  "rollout_hints": ["feature flag/canary 전략"],
  "rollback_hints": ["가장 빠른 롤백 경로"],
  "validation_hints": ["실행한 검증 명령어"],
  "review_notes_hints": ["리뷰어 우선 확인 포인트"],
  "check_hints": ["실제 CI 체크명 참조"],
  "preferred_spec_paths": ["docs/specs/**"],
  "preferred_guide_paths": ["README.md"],
  "extra_instructions": ["추가 지시사항"]
}
```

**힌트 카테고리 8가지**: spec, guide, oracle, rollout, rollback, validation, review_notes, check

## Onboarding 프로세스

1. 중앙 레포의 `scripts/onboard_repo.py` 실행
2. 레포 프로필 자동 추론 (e.g. `frontend/monorepo`)
3. 3개 파일 자동 생성 → PR 생성 (e.g. PR #6445)
4. 머지 후 즉시 PR 이벤트 스코어링 시작

## 설계 원칙

| 원칙 | 구현 |
|------|------|
| **중앙 집중** | 스코어링 로직은 중앙 레포에만 존재 |
| **레포 자율** | `scoring.yml`, `pr-authoring.json`은 레포 소유자 관리 |
| **최소 침습** | Caller 14줄 + 설정 2파일로 온보딩 완료 |
| **자동 갱신** | 중앙 로직 개선 시 전체 레포에 자동 반영 |

## Flashcards
#flashcards

Harness Scoring System의 레포 온보딩에 필요한 파일 3가지::1) `.github/workflows/harness-scoring.yml` (Caller workflow, 14줄) 2) `.harness/scoring.yml` (프로필, 팀 매핑) 3) `.harness/pr-authoring.json` (PR 작성 힌트)

Harness Scoring의 pr-authoring.json 힌트 카테고리 8가지::==spec==, guide, oracle, rollout, rollback, validation, review_notes, check — PR 품질의 다면적 평가 기준

Harness Scoring이 Reusable Workflow를 사용하는 이유::중앙 레포에 스코어링 로직을 집중시켜, 로직 개선 시 전체 레포에 자동 반영. 각 레포는 ==14줄== Caller + 설정 2파일만 필요
